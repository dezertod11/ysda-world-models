## Почему именно этот объём

Нужно проверить воспроизводимость всей основной таблицы после исправления
runtime state, а затем устойчивость к stochastic rollout seeds на одной
версии. Один удачный seed недостаточен; выбирать лучший seed по итогам нельзя.
Три повтора дают описательный межseed разброс, но не доказывают unseen-task
transfer и не заменяют доверительные интервалы по task/init clusters.

На старте свободны 7 H100; GPU3 занята другим процессом. Оценка для семи
доступных GPU: примерно 6-9 часов, без гарантии их дальнейшей доступности.
Оставшийся резерв предназначен для ожидания ресурсов и аудита.
Ресурсы освобождаются сразу после завершения, не удерживаются до deadline.

## Что будет сохранено

- По каждой полной серии: Object/Environment/Position SR, Macro-SR,
  success count, paired effects/cluster CI/Holm, query metrics и видео.
- Общая CPU-сводка: таблицы каждого seed; mean/std только полных серий;
  rescue/harm; event coverage; проверка начальных observation hashes.
- Галерея всех matched случаев с различными исходами, включая harms.

Std по трём seeds является описательной характеристикой, не CI по задачам.
Неполные серии обозначаются как partial и не входят в aggregate inference.
Новые результаты не дописываются автоматически в финальные утверждения статьи
без содержательного разбора. Цель запуска: надёжность evidence, не гарантия
принятия статьи или улучшения SR.
