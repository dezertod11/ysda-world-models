# GPU0-7: ресурсная поправка без совместного запуска на занятой карте

Дополнение: [resident worker](RESIDENT_WORKER_PROTOCOL_20260909.md) переносит
idle-проверку на начало пакета до 8 совместимых reference jobs. Внутри пакета
модель не выгружается между заданиями. Пороги допуска и запрет на вмешательство
в чужие процессы остаются прежними; P5 этим дополнением не меняется.

9 сентября 2026 года. Пользователь разрешил физические GPU **0-7** при
условии, что это не нарушит другие вычисления. Прежний запрет GPU0 для
этой очереди заменён явным допуском при проверенной незанятости.

## Что применено

- Текущая цепочка references -> P5 smoke -> P5 pilot использует общий пул
  GPU0-7. Default launcher и передаваемые дочернему runner аргументы обновлены.
- GPU0 допускается только с `--allow-gpu-zero` и `dynamic_gpu_queue=true`.
  Статическая очередь с GPU0 отклоняется. Проверенный worker передаёт
  `MLSPACE_ALLOW_GPU0=1` shell-окружению; без явного допуска shell отвергает GPU0.
- Перед каждым новым job: memory.used <256 MiB, utilization <5%, список
  CUDA compute-процессов пуст. Требуются две проверки с интервалом 2 секунды.
  Ошибка, timeout или неизвестное значение `nvidia-smi` означают отказ от запуска.
- Занятая GPU не резервирует job; другую свободную карту может использовать
  любой worker общей очереди. На одну карту приходится один наш worker.
- Низкая utilization при существующем процессе не считается разрешением
  на совместное использование. Порог памяти не ослаблен.

## Перезапуск и сохранность

Диспетчер перезапущен **в 13:44:54 MSK**, новый PID **2694673**.
В **13:45:44 MSK** проверены свежий heartbeat, stage `reference_references`
и дочерний PID **2696597**, получивший `--gpus 0,1,2,3,4,5,6,7 --allow-gpu-zero`.
В момент проверки все восемь workers ожидали освобождения карты.

**Повторная проверка в 13:51:48 MSK:** GPU0 и GPU2 освободились, и очередь
автоматически запустила два collector: PID **2702888** на физической GPU0,
PID **2702600** на GPU2. Список CUDA compute-процессов подтвердил, что на
каждой из этих двух карт находится только наш collector. На остальных
картах продолжаются чужие вычисления; очередь не запускает туда модели.
Следовательно, после ожидания возобновился не только диспетчер, но и
реальный GPU rollout. Это снимок состояния, не резервирование карт.

До перезапуска завершено **128 jobs / 368 reference rollout**.
Старые supervisor/campaign runner остановлены только между jobs после
проверки отсутствия дочерних заданий. Все 128 completion markers проверены
по SHA после перезапуска: ни один не изменён. Готовые эпизоды пропускаются
по markers/resume, seeds и модели не менялись. Осталось 229 reference
rollout; P5 пока не начался.

Изменены только ресурсный launcher, campaign admission и явный допуск в
shell environment. Старый `freeze.json` сохранён с тем же SHA:

```text
8c6665496fb3416832ef8fd08f9dcd196ed87aeba8dc9618ba7ea4d5901f5c6b
```

Новая поправка связывается с исходным freeze и прежней GPU1-7 поправкой
контрольными суммами. Изменение collector, config, benchmark support,
model runtime или P5 settings под видом этой поправки отклоняется.
Предыдущее содержимое изменённых файлов, manifest и статус сохранены
в `resource_gpu07_backup`; не удаляются готовые traces/videos.

## Граница гарантии

**Это консервативный допуск на свободную карту, не аппаратная изоляция.**
Между проверкой и стартом другой пользователь может запустить своё задание;
наша очередь не умеет резервировать карту у всех пользователей сервера.
Также GPU-проверка не резервирует общие CPU/RAM. Поэтому абсолютная гарантия
от взаимного влияния требует согласованного бронирования или общего
планировщика ресурсов; MIG является отдельной административной настройкой.
Чужие процессы не завершаются, не приостанавливаются, их лимиты не меняются.

Мониторинг из WSL:

```bash
./scripts/mlspace_experiment_status.sh consensus_p5_night_20260909
./scripts/mlspace_experiment_status.sh consensus_references_20260909_valid199
```

`RUNNING` с heartbeat и сообщениями `waiting for free GPU` означает живой
диспетчер, но не обязательно работающую GPU-модель. ETA не включает
неизвестное ожидание чужих вычислений.
